# GeoCheck — дашборд доступности сайта из разных стран

Инструмент для проверки «доступен ли сайт из страны X» с фокусом на CloudFlare
(челленджи, cf-mitigated, CF-RAY, 5xx из CF-зоны) и на различия между зеркалами
(например `example.com` vs `ru.example.com` vs `example.ru`).

## Архитектура

```
┌─────────────────────────── статическая страница (index.html) ───────────────────────────┐
│  Кнопка «Запустить проверку»                                                            │
│    ├──► check-host.net API  (HTTP/pi/ng/tcp из ~30 узлов)   — прямо из браузера        │
│    ├──► GlobalPing API      (сотни проб по миру)             — прямо из браузера        │
│    └──► http://127.0.0.1:8787 — локальный демон (только на машинах, где он запущен)    │
└─────────────────────────────────────────────────────────────────────────────────────────┘
                                          │
┌──────────────── daemon/checkdaemon.py (Python 3.10+, только Windows-окружение с curl) ─┐
│  • читает подписки VPN (env RG_SUBS или POST из дашборда) — ТОЛЬКО в памяти            │
│  • извлекает конфиги (vless/vmess/trojan/ss), поднимает ядра HiddifyCore (sing-box)     │
│    на 127.0.0.1:21000+ — tun НЕ создаёт, работающий VPN-клиент не мешает               │
│  • гоняет curl-замеры (код, тайминги разложены, CF-RAY, cf-mitigated) по доменам        │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

## Быстрый старт

### 1. Дашборд (для всей команды)

Статика — хостится куда угодно (GitHub Pages, S3, внутренний nginx, Kimi-публикация):

```bash
cd geocheck
npm run dev        # локально: http://127.0.0.1:7100/  (server.js пробрасывает --host/--port)
```

Для команды достаточно отдать папку `geocheck` без `daemon/` любому статическому хостингу.
Внешние проверки (check-host.net, GlobalPing) работают у каждого, кто открыл страницу, — ключи не нужны.

### 2. Локальный демон (кто хочет «свои» VPN-страны)

```bash
set RG_SUBS=https://ваша-подписка-1;https://ваша-подписка-2   # опционально
python daemon/checkdaemon.py                                   # 127.0.0.1:8787
```

Либо без env: в настройках дашборда (⚙) вставить URL подписки в поле «Подписки VPN»
и нажать «Отправить на демон». URL уходят только на `127.0.0.1`, нигде не сохраняются.

Переменные окружения демона:

| Переменная       | Назначение                                             |
|------------------|--------------------------------------------------------|
| `RG_SUBS`        | URL подписки (через `;` или перевод строки)            |
| `RG_DAEMON_PORT` | порт демона (по умолчанию 8787)                       |
| `SINGBOX_PATH`   | путь к `sing-box.exe`/`HiddifyCore.exe`, если автопоиск не нашёл |

Ядро ищется автоматически в установках Hiddify (`C:\Program Files\Hiddify\HiddifyCore.exe`,
используется команда `srun`). Демон требует curl.exe в PATH (есть в любой Windows 10/11).

## Развёртывание на Raspberry Pi (maxpi)

Цель: демон работает на Pi постоянно, доступен из домашней сети и из Tailscale, открыт только с токеном.
Pi: Debian 13 arm64, 8 ГБ RAM, системный chromium, без VPN-клиента. Порт по умолчанию 8787.

```bash
# с ПК (Git Bash / Linux / macOS), из корня репозитория
deploy/deploy.sh                       # релиз HEAD + секреты из корня проекта + запуск + проверка /status
deploy/deploy.sh --prepare-only        # только залить релиз, секреты, venv, sing-box и токен (без запуска)
deploy/deploy.sh --no-secrets          # переразвернуть код, секреты на Pi не трогать
deploy/deploy.sh --secrets-dir D:\keep # секреты берутся из другой папки
```

Что делает `deploy.sh` (повторяемо, можно запускать снова):
1. Упаковывает **закоммиченный** HEAD (`git archive`): незакоммиченное и секреты в релиз не попадают.
2. Заливает в `~/geocheck/releases/<rev>` и переключает `~/geocheck/current`.
3. Стримит `subs.txt` и `user_nodes.txt` в `~/geocheck/secrets/` с правами 600; сверяет sha256.
4. Запускает `deploy/pi-install.sh` на Pi: venv с Playwright, sing-box linux-arm64 (версия закреплена в
   `SINGBOX_VERSION`), `geocheck.env` с токеном (создаётся один раз), `config/domains.txt`, systemd-юниты.
5. Проверяет `GET /status` с токеном (токен читается на Pi, в консоль не выводится).

Раскладка на Pi:

```
~/geocheck/
  releases/<rev>/      код (без секретов)
  current -> releases/<rev>
  venv/                Python, playwright
  bin/sing-box         ядро sing-box 1.14.4 (linux-arm64)
  secrets/             700: subs.txt, user_nodes.txt, geocheck.env (600)
  config/domains.txt   домены для плановых проверок (не секрет)
  data/runs/           результаты плановых проверок (JSON)
```

systemd (`deploy/systemd/`):
- `geocheck.service` — демон, перезапуск при сбое (`Restart=on-failure`).
- `geocheck-fw.service` — правила iptables: порт только из `127.0.0.0/8`, `192.168.0.0/24`, `100.64.0.0/10`.
- `geocheck-scan.timer` + `geocheck-scan.service` — плановая проверка доменов из `config/domains.txt` в 03:00 и 15:00 (время Pi).

Управление на Pi: `systemctl status geocheck`, `journalctl -u geocheck -n 100`, `systemctl list-timers geocheck-scan.timer`.

Доступ: `http://<адрес-Pi>:8787/` с токеном из `~/geocheck/secrets/geocheck.env`. Адрес Pi в домашней сети
сейчас `192.168.0.192`, в Tailscale — `100.73.113.77`. Токен никуда не копируется: его показывает только файл на Pi.

Ограничения Pi: 4 ГБ свободного места на SD-карте (30 ГБ раздел, занято 86%); один браузерный прогон за раз
(`concurrency 1–2`), иначе не хватит памяти рядом с другими сервисами Pi.

## API демона

| Метод/путь                | Тело                       | Ответ                                   |
|---------------------------|----------------------------|-----------------------------------------|
| `GET /status`             | —                          | `{ok, version, exits:[{id,label,port,status}]}` |
| `POST /set_subscriptions` | `{urls: [...], inline: [...]}` | `{ok, exits, warnings}` — пересоздаёт выходы; `inline` — список текстов с vless://-ссылками, вставленных напрямую (без скачивания) |
| `POST /run`               | `{domains: [...]}`         | `{ok, results:{exitId:{domain:{code,ms,timings,cfRay,cfMitigated,ip,error,headers}}}}` |

CORS открыт только для удобства браузера (`Access-Control-Allow-Private-Network: true`),
слушает исключительно `127.0.0.1` — снаружи недоступен по построению.

## Модель безопасности (секреты)

Правда о том, где что лежит (исправлено 2026-11-22; прежняя формулировка «только в памяти» была неверной):

1. **Файлы с секретами читает демон при старте:** `subs.txt` (URL подписок и/или `vless://`) и
   `user_nodes.txt` (ссылки). Они лежат в папке `RG_SECRETS_DIR` (по умолчанию — корень проекта рядом с демоном).
   В git не попадают (`.gitignore`), в релиз на Pi не копируются, в дашборд не отдаются.
2. **На Raspberry Pi** файлы лежат в `~/geocheck/secrets/` (права `700` на папку, `600` на файлы), вне
   `releases/` и вне веб-корня. Токен доступа — `~/geocheck/secrets/geocheck.env` (`RG_TOKEN`, `600`).
3. Содержимое секретов не выводится в логи, отчёты и чат. Деплой проверяет только размер и sha256.
4. Ссылки подписок и ключи не передаются в URL и не уходят никуда, кроме скачивания самой подписки
   (и запросов к её серверам через sing-box).
5. Дашборд не содержит секретов; настройки (домены, тумблеры, порт демона) — в localStorage браузера.
6. Демон на Pi слушает LAN и Tailscale с токеном (`Authorization: Bearer <RG_TOKEN>`); порт закрыт
   для остальных адресов правилами `deploy/firewall.sh`. Наружу в интернет ничего не открыто.
7. Из VPN-подписок в `user_nodes.txt` и `subs.txt` ничего не публикуется; экспорт JSON/CSV содержит
   только результаты проверок (коды, тайминги, IP выхода, страну).

## Интерпретация результатов (CloudFlare-aware)

| Симптом                          | Вероятная причина                                          |
|----------------------------------|------------------------------------------------------------|
| `403` + `cf-mitigated: challenge`| CloudFlare-челлендж (бот-блок по гео/ASN/IP-репутации)     |
| `5xx` + `CF-RAY`                 | origin не отвечает / CF сам обрывает сессию                |
| обрыв на TCP/TLS (ERR, < 1 c)    | режется сеть (провайдер/exit-узел/гос-DPI), не дошли до CF |
| `200` везде, кроме одной страны  | гео-политика CF (country block) или блок по ASN этой страны|
| ok извне, ERR локально           | проблема на пути от вашей машины (VPN exit, DNS, провайдер)|

## Известные ограничения

1. **tun-VPN на машине может резать handshake до серверов прокси.** Если у вас
   запущен VPN-клиент в TUN-режиме, чьи exit-узлы фильтруют TLS-рукопожатия
   (например VLESS-Reality), локальные прокси-выходы демона будут «обрыв/таймаут»,
   хотя сами серверы живы. Обходы: (а) другой exit у системного VPN; (б) запуск
   демона без tun-VPN; (в) админ-права + хост-маршруты `route add <ip> mask
   255.255.255.255 <шлюз>` для IP серверов подписки (вне скрипта, вручную).
2. `HiddifyCore run` (режим с фрагментацией) — один инстанс на машину: GUI Hiddify
   держит gRPC-порт 17078. Демон использует `srun`-режим, ограничения нет.
3. Системный DNS под tun-VPN может отдавать fake-ip (`198.18.x.x`). Демон резолвит
   серверы подписки через DoH (1.1.1.1) — это учтено; fake-ip в колонке «ip»
   означает, что замер шёл через tun мимо прокси.
5. Ядра sing-box, умершие между прогонами, демон перезапускает автоматически
   (`ensure_cores` в начале `/run` и `/warmup`). Если нода стабильно «серая» —
   перепроверьте ячейку кнопкой ⟳ или перезагрузите подписки (ротация серверов).
4. check-host.net бесплатен и без ключа — у него есть мягкие лимиты; при злоупотреблении
   прогоны начнут отдавать частичные результаты (дашборд это показывает как пустые ячейки).
6. **VPN-выходы — это датацентровые IP, а не домашние.** Большинство нод подписки стоят в дата-центрах
   хостеров. Сайты, которые режут датацентровые диапазоны, покажут блок у VPN-выхода, хотя обычный
   пользователь из той же страны пройдёт. Поэтому «ERR/403 через VPN» не равно «сайт недоступен в стране».
   Выводы о доступности для обычных пользователей делайте по прямому каналу и по check-host/GlobalPing
   (тоже датацентровые пробы, но других провайдеров). GeoIP-проверка показывает страну реального выхода
   и отмечает расхождение с заявленной; мёртвые выходы помечаются `exit down` и не входят в вердикт.
7. Pi находится в домашней сети: его прямой канал — это домашний провайдер, а не страна назначения.
   Для проверки «из России» Pi нужен VPN-выход или внешняя проба, сам по себе он этого не даёт.

## Изменения 2026-11-22 (Квилл)

- Демон проверяет `Host` (только loopback) и `Origin` (по умолчанию `http://127.0.0.1:7100`, `http://localhost:7100`; свои — `RG_ORIGINS=https://host1,https://host2`). Чужие сайты в браузере больше не могут управлять демоном.
- При старте демон сам читает `subs.txt` (URL подписок и/или `vless://`-ссылки) и `user_nodes.txt` рядом с проектом; `RG_MAX_EXITS` (по умолчанию 40) ограничивает число нод, при обрезке есть предупреждение.
- Конфиги ядер и временные файлы лежат в приватной временной папке и удаляются при выходе; ядра гасятся вместе с демоном.
- Пробник принимает только `http(s)://` и передаёт URL после `--` (раньше строка вида `--output=...` попадала в curl как опция).
- Ошибки curl классифицируются по коду выхода, а не по подстроке «97» в тексте.
- Убран нерабочий `GET /run`; `/warmup`, `/fwd` существуют (см. выше).
- check-host и GlobalPing: все домены меряются одними и теми же узлами/пробами, перепроверка строки идёт на тот же узел. Раньше узлы для каждого домена выбирались случайно.
- UI: поле подписок принимает и `vless://`; кнопка запуска не зависает после прерванного прогона; перепроверки не пишутся в историю; в заголовке вкладки — таймер прогона.

## Браузерная проверка и статусы (2026-11-22, Квилл)

Включается галочкой «браузерная проверка выходов» (настройки) и запросом `/run` с `{"browser": true}`. Для каждого выхода запускается `daemon/browser_probe.py`: настоящий Chrome/Edge через SOCKS ядра (нужны Python-пакет `playwright` и установленный Chrome или Edge). В браузере параллельно идут 4 проверки, curl-режим — 16.

Статусы ячейки:

| Статус | Что значит | Считается сбоем |
|---|---|---|
| `200 · 1.2s` и т.п. | страница загрузилась | нет |
| `медленно N s` | загрузка дольше порога `slowMs` (по умолчанию 10 с, в настройках) | да |
| `ERR · …` | страница не грузится вовсе (`ERR_TIMED_OUT`, сброс, туннель выхода недоступен) | да |
| `🛡 Send · N s` | сайт показал заглушку антибота с формой `.ab_check_form`; Send нажимается один раз, время — по факту загрузки (в подробностях: заглушка + загрузка после Send) | нет, если прошла |
| `🛡 Send не прошёл` | после нажатия Send страница не открылась | да |
| `⛔ nginx 503 (антибот)` | жёсткий антибот сайта: nginx «503 Service Temporarily Unavailable». Это НЕ заглушка со Send. Не обходим | нет |
| `домен не грузится` | включён режим «сначала домен», корень домена не открылся, страница не проверялась | да |

Решения владельца: Send жмётся только на заглушке с формой; nginx-503 отличается от неё и от настоящих ошибок; обязательно мерить время загрузки; проверки идут одна за другой; сначала проверка по домену (галочка «сначала проверять домен, потом страницу», `domainFirst`).

Проверочный прогон 22.11, страница Внуково на `restaurantguru.ru`, 41 выход: nginx-503 — 28, домен не грузится (туннель выхода недоступен) — 10, медленно (18,7 с) — 1, нормально — 2 (в том числе прямой канал, 3,6 с). Заглушка со Send на живой странице не встретилась: нажатие проверено только на уровне кода.

## Публичная форма и приватные настройки (Raspberry Pi)

Один демон, два порта:

| Порт | Кто видит | Что отдаёт |
|---|---|---|
| `8787` (приватный) | только LAN `192.168.0.0/24`, Tailscale и loopback (файрвол), плюс токен `RG_TOKEN` | дашборд, `/api/*`, запуск прогонов с VPN-выходами, история, настройки |
| `8788` (публичный) | только loopback; в интернет его выводит Tailscale Funnel | форма `public.html` и `POST /pub/check`, `GET /pub/job/<id>` |

Публичная часть проверяет только «прямым» каналом сервера (без VPN, без браузера), до 5 адресов за раз,
не больше 6 проверок за 10 минут с одного адреса и 60 в час на всех; адреса во внутреннюю сеть
(частные и loopback IP, порты кроме 80/443, `.local`, `.ts.net`) отклоняются, редиректы не выполняются.
Публичный порт не знает про токен, подписки, выходы и историю: этих маршрутов в нём нет.

Включить публичную ссылку на Pi: `sudo tailscale funnel --bg 8788`; выключить: `sudo tailscale funnel --https=443 off`.
Токен лежит на Pi в `~/geocheck/secrets/geocheck.env` (mode 600); из чата и логов он не читается.
Всё хранится на SSD (`/home/jg/data/geocheck`), на SD-карту ничего не пишется.
